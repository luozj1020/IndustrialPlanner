# 明日方舟：终末地集成工业规划器

Arknights Endfield Industrial Planner 是一个运行在浏览器里的《明日方舟：终末地》集成工业产线布置、蓝图管理与仿真工具。

你可以不用打开游戏，就先在网页里摆产线、接传送带、配物流、跑仿真、查配方、规划生产链路、保存蓝图，把它当成网页版产线练习场、验证器和草稿本来用。

## 在线使用

- 国际站：https://endfield.anonymous-test.top/
- 中国大陆 CDN：https://endfield.amiyabot.com/

当前版本支持桌面端、平板端和手机横屏使用。手机竖屏会显示旋转提示；如果要进行复杂编辑、长时间仿真或大规模蓝图整理，桌面端仍然是效率最高的使用方式。

兼容浏览器中可以启用离线使用并添加到桌面。离线资源准备完成后，即使断网也可以打开和使用主要功能。

![产线布置预览](.github/readme-assets/layout-preview.png)

## 主要能力

- 规划一整条产线，不用反复进游戏试错。
- 验证传送带、管道、分流汇流、端口配置、物流优先级是否能跑通。
- 用仿真快速定位缺料、堵塞、供电不足、节拍不匹配等问题。
- 查询物品、建筑、配方和生产链路。
- 使用产线规划器按目标产量反推设备数量、输入消耗和物流吞吐。
- 使用模块配平工具组合系统配方与自定义模块，评估阶段净产出和库存压力。
- 保存、恢复、复制、导入、导出和复用蓝图。这里的蓝图是网页工具内的布局数据，不是游戏内可直接导入的蓝图。

## 相比游戏内更方便的地方

- 支持虚空生产物品，尤其适合流体调试。抽水泵、暗管出口等设备可以配置无限来源；出货口可以无视库存限制直接取出物品。
- 设备内预置物品可以跟随复制和蓝图保存，适合记录协议存储箱、投料箱等带初始内容的模块。
- 可以临时重叠放置建筑，便于移动和改造拥挤产线，调整完再拆开。
- 支持最高 16 倍速仿真，用更短时间观察产线趋势和堵塞位置。
- 可以切换真实供电或无限供电，设置基地初始电量，并模拟电力不足。

## 当前功能

### 产线编辑

- 支持放置、旋转、移动、删除建筑。
- 支持点选、框选、多选、增减选区、批量移动、批量删除和选区保存蓝图。
- 支持直接铺设传送带与管道，并自动处理部分连接逻辑。
- 支持通过传送带叠放生成分流、汇流等结构。
- 支持多基地切换和不同基地规格下的布局规划。
- 支持快捷键、触控操作、视角缩放、视角旋转和多种操作模式配置。

### 蓝图工作流

- 支持正式蓝图、本地蓝图、公共蓝图和临时蓝图。
- 支持复制选区为临时蓝图、粘贴投放、保存为正式蓝图。
- 支持蓝图导入、导出、分享与复用，适合沉淀标准化模块。
- 支持协议核心随蓝图处理，并在正式放置前做必要确认。
- 保存正式蓝图时会剔除建造区域外设备，避免保存出不可用内容。

### 仿真与调试

- 支持开始、暂停、退出仿真和多档速度。
- 支持查看设备运行状态、缺料、堵塞、内部缓存和运行结果。
- 支持统计产出、消耗、库存与过程信息。
- 支持完整电力仿真、无限供电、初始电池百分比和耗电调整。
- 支持物流顺序、端口优先级、仓储格子、预置物品等复杂配置。
- 当前仿真默认完整计算当前活动基地，跨基地流程更适合作为近似规划参考。

### 规划与查询

- 内置百科，支持物品、建筑、配方查询和生产链路浏览。
- 产线规划器支持目标产出、外部输入、来源策略、设备视图、物品视图和流程图视图。
- 模块配平支持系统模块、自定义模块、多阶段配平和阶段净差值统计。
- 提供帮助面板、操作说明、版本更新记录和中英双语界面。

### 持久化与离线

- 支持撤销、重做和操作历史时间线回跳。
- 刷新页面后会保留当前基地的操作历史和常用设置。
- 版本升级时会自动处理旧数据迁移或丢弃不兼容历史，避免兼容错误。
- 支持 PWA 离线资源缓存、离线更新提示和添加到桌面。

## 适合验证的场景

- 新版本产线预规划。
- 复杂物流结构联通性检查。
- 电力覆盖、供需关系和电池策略验证。
- 协议核心、优先级端口、预置物品、仓储规则等复杂设施调试。
- 模块化产线配平、产能估算和物流吞吐估算。
- 攻略配图、录图、截图和布局方案分享。

## 本地开发

项目基于 React、MobX、PixiJS、Vite、Vitest 和 TypeScript。

### Headless 占地与物流优化

无需启动网页即可按目标产量反推设备数量，在指定矩形范围内铺设生产设备、传送带和管道，
并生成可导入的蓝图：

```bash
npm run headless -- items iron
npm run headless -- recipes item_iron_nugget
npm run headless -- graph examples/headless/dense-originium-powder-topology-baseline-request.json \
  --output examples/headless/dense-originium-powder-device-graph.svg \
  --json examples/headless/dense-originium-powder-device-graph.json
npm run headless -- optimize examples/headless/iron-nugget.json \
  --output optimized-blueprint.json --report optimization-report.json \
  --svg optimized-layout.svg
npm run headless -- optimize examples/headless/liquid-xiranite.json \
  --output liquid-blueprint.json --report liquid-report.json
npm run headless -- optimize examples/headless/dense-originium-powder.json \
  --output dense-powder-blueprint.json --report dense-powder-report.json \
  --svg dense-powder-layout.svg
npm run headless -- optimize examples/headless/dense-cluster-26x28-request.json \
  --output examples/headless/dense-cluster-26x28-blueprint.json \
  --report examples/headless/dense-cluster-26x28-report.json \
  --svg examples/headless/dense-cluster-26x28.svg
```

`search.refinementCandidates` 控制初始布局和后续每个改进阶段真正进入完整物流验证的候选数，
默认 12、范围 1～48。较小值适合快速迭代，较大值用于离线深度搜索；优化器始终保留确定性
基线，并在仓库扇出、设备交换、临街移动、CP-SAT 与普通启发式候选之间轮转取样，避免单一
操作族耗尽 A* 预算。该值和 `search.routingVariants` 控制正常快速路径；只有整束候选都不可
路由时，系统才最多追加 8 个候选，并只对失败进度最深的 4 个布局追加最多 2 种路由顺序。

复杂布局可选用本地 OR-Tools CP-SAT 生成约束布局候选，再交给内置 LNS 与 A* 做实际物流验证：

```bash
python -m venv .venv-headless
.venv-headless/bin/python -m pip install -r requirements-headless.txt
INDUSTRIAL_PLANNER_PYTHON=.venv-headless/bin/python npm run headless -- optimize \
  examples/headless/dense-originium-powder.json --output dense-powder-blueprint.json
```

Windows 下 Python 路径通常为 `.venv-headless/Scripts/python.exe`。未安装 OR-Tools 或未找到指定
Python 时，优化器会自动回退到确定性 LNS，不依赖在线服务。

输入 JSON 的核心字段为 `width`、`height` 和 `targets`；还可指定 `supplies`、
`infiniteItemIds`、`recipeChoices`、`minimumRecipeDeviceCounts`、`baseId`、`allowRotate`、
`routingClearance` 与 `search`。`minimumRecipeDeviceCounts` 可把理论负载分摊到更多同配方设备，
用于满足一口一机、减少单端口合流或扇出的可行性要求；它不改变总输入和总输出吞吐。
`search.iterations` 控制大邻域排列搜索次数，`search.routingVariants` 可取 1–9，
`search.refinementCandidates` 控制初始快速束和改进阶段的昂贵路由候选，
`search.seed` 用于复现实验。`search.initialLayout` 可设为 `topology-sequential`，只从生产流图
派生的顺序基线开始；`search.scope` 可设为 `local`，只执行保持拓扑层成员关系的局部移动，
不允许层级交错、全图 fan-out 搬迁、ejection chain、CP-SAT 或全局重建。全局作用域可用
`search.globalNeighborhoods: "layer-interlock"` 只开启宽度证明后的层级交错；默认 `"all"`
保留全部全局邻域。报告会原样记录这些字段，便于确认实验阶段没有混用。
`search.cpSat.enabled` 开启 CP-SAT 候选，
`maxSeconds` 是整批 CP-SAT 候选共享的求解时间预算，`candidates` 是该预算内最多尝试的
候选数量；它不会把总时限按候选数倍增。报告中的 `cpSatBudgetSeconds`、
`cpSatAttemptedCandidates`、`cpSatStoppedBy` 和 `cpSatElapsedMs` 可用于核对实际消耗。输出蓝图
可由本项目现有蓝图导入流程读取，并在 Node 环境通过拓扑编译器校验。
`routingClearance` 表示布局外缘预留的物流缓冲。生产设备之间不再强制统一净空，允许直接相邻；
候选布局必须保留实际配方所需的输入/输出端口，并通过 A* 路由和物理拓扑验证。
旋转搜索会对正方形和长方形设备完整尝试 `0/90/180/270°`；长方形在 `90/270°`
时同步交换占地宽高，`180°` 则保留占地但反转端口朝向。

物料流会按物流设施的实际吞吐拆分：传送带每 2 秒运输 1 个物品，即单 lane 为 30/min。
例如致密源石粉末配方每台每 2 秒消耗 2 个源石粉末，因此满速时每台必须使用两条源石粉末
输入 lane。拓扑连通之外，报告还会给出 `productionThroughputVerified` 吞吐验收结果。

致密源石粉末示例从源矿开始生产源石粉末；砂叶采用闭环配平：两台种植机每分钟合计产出
60 砂叶，一台采种机消耗 30 砂叶并恢复两台种植机所需的 60 种子，剩余 30 砂叶供一台
粉碎机满速生产 90 砂叶粉末。

固体产线会生成实际仓储物流：缺口原料通过附着于存储基段的取货口进入，并生成仓库 slot link；
终产物输入协议存储箱即视为完成存货，不再额外串联存货口。
液体目前仍使用管道边界，后续由液体储罐和暗管口接替。

整体算法先从生产规划结果构造逐设备物料流图，将不可摆放且无端口的自然资源伪设备转换为
边界供料；外层用交换、插入和区间反转执行确定性大邻域搜索，并为每种排列尝试面积优先、
方正优先和横向生长三种 bottom-left 放置策略。内层尝试端口受限优先、长线优先和短线优先
三种连接顺序，再执行带转弯与交叉惩罚的多目标 A*。垂直物流允许自动升级为项目原生的
跨线连接器；得到可路由布局后，再逐台设备做小步平移、尝试全部端口朝向并重新布线，
以消除外圈物流格（正方形设备也会旋转，因为端口方向仍会变化）。
最终按硬约束、取货口前沿溢出、轴对齐包围盒面积、计费占地轮廓面积、物流格数、
转弯与交叉代价、轮廓空位和最长边依次选优。生产设备、
协议存储箱及其入库传送带计入占地；取货口到生产设备的供料传送带仍会完整生成和验证，
但不参与面积评分。报告同时给出优化口径和包含免费供料带的完整物理包围盒，
避免短物流支线形成细长外轮廓，并用模拟拓扑
的物理连接与诊断结果验收。

### 自动铺设与优化流程

自动优化并不是先随意摆放设备、最后再补传送带，而是将生产规划、设备布局、端口分配和
物流路由作为相互约束的多阶段搜索问题。完整流程如下。

#### 阶段一：读取请求并校验

优化器读取目标区域、目标产量、外部供给、无限来源、配方选择、旋转策略、物流余量和搜索参数。
`width`、`height` 必须是正整数，目标产量必须大于零；`search.iterations` 范围为 0～500，
`search.routingVariants` 范围为 1～9，`search.refinementCandidates` 范围为 1～48。
CP-SAT 整批候选共享的求解预算上限为 30 秒，候选数上限为 12。请求不合法时会在生产规划和
布局搜索前直接报错。

#### 阶段二：按目标产量反推生产链

系统从每个目标物品开始递归展开需求。每层先扣除手工供给、可复用副产物和无限来源，再依据
`recipeChoices` 或默认配方计算所需循环次数、设备数、输入和副产物。自然资源优先采用无输入
采集配方；水、酸和污水则根据 `sourceConfig` 决定使用副产物、倾倒或外部供给。若递归结束后
仍存在既不能生产又没有来源的输入，优化立即失败，并列出每种未解决物品的每分钟缺口。

#### 阶段三：实例化生产设备

理论设备数按 `ceil(deviceCount - 浮点容差)` 转换成实际设备实例，每台实例分别记录配方、
满速输入输出、默认配置和配方通道。没有物理端口的自然资源伪设备不会摆入地图，其产物在
路由阶段转换为边界来源。任意配方循环都会先由配方—物料图的强连通分量识别，再根据匿名净流量
矩阵求满足内部回流与外部需求的最小整数设备组合；该过程不读取配方名、物品名或设备 ID。

#### 阶段四：补全仓储输入和产品存储

生产设备之间先按物品分配内部产出。固体输入仍有缺口时，系统按单条传送带吞吐拆分缺口，
为每条 lane 创建仓库取货口，并建立协议仓库 slot link；固体目标产品则创建协议存储箱，
记录所有直接生产者。系统还会按取货口数量生成仓库总线源和总线段。液体缺口目前仍转换为
地图边界管道来源。

#### 阶段五：构造逐 lane 物料流图

每项输入和输出都会按实际物流容量拆成独立连接：

$$
L_e=\left\lceil\frac{q_e}{C_e}\right\rceil,
$$

其中 $q_e$ 是连接 $e$ 的每分钟流量，$C_e$ 是对应物流设施单 lane 的每分钟容量。

传送带每 2 秒运输 1 个物品，因此单 lane 为 30/min。设备需要 60/min 固体原料时必须生成
两条连接、使用两个输入端口。连接可能是设备到设备、边界到设备、设备到边界、仓库取货口到
生产设备，或生产设备到协议存储箱。端口数不足时不会合并或虚构连接，而是明确判定不可行。

#### 阶段六：生成初始设备布局候选

优化器并行考虑多类确定性候选：

- 按共同终端组织的生产流簇；
- 按上下游依赖分层的流水布局；
- 上游到下游、依赖紧密度、面积、长边、短边、宽度和高度等排序；
- 由交换、插入和区间反转产生的大邻域排列；
- 面积优先、方正优先、横向或纵向生长、物料流距离与端口朝向优先等 bottom-left 放置评分。

每台设备会尝试所有合法坐标和允许的旋转。设备可以直接相邻，`routingClearance` 不等同于
设备间强制统一净空；候选最终是否可行仍由真实端口可达性和完整物流路由决定。

需要从头核对产线顺序时，将 `search.initialLayout` 设为 `topology-sequential`。此模式只保留
由逐 lane 物料流图构造的仓库顺序基线，不混入普通打包、仓库 fan-out 插入或 CP-SAT 候选。
算法先固定实际生产者—消费者分配，再求强连通分量和缩点 DAG。最长路径层号只作为初始偏序，
不会直接进入设备铺设；容量感知的 ready-set 调度会在生成坐标之前重新拆分同层分量。设备坐标、
横向/纵向展开及循环块折行均由图、设备尺寸、端口和通道容量派生，不按配方名称或某个示例形状
分支。横排和竖排只是几何映射，必须保持的是有向图偏序以及循环分量内部的反馈关系。

##### 层次设计阶段的可行性证明

设已经安排到前序层的分量集合为 $S_{<k}$，当前拓扑 ready 集合中拟放入第 $k$ 层的分量集合为
$L_k$。仍需从前序层穿过当前层、抵达更晚层的 lane 数为：

$$
T_k=
\sum_{\substack{
e=(u,v)\\
u\in S_{<k}\\
v\notin S_{<k}\cup L_k
}}
\ell_e.
$$

令 $B_k$ 为 $L_k$ 中设备或 SCC 折叠块的乐观最小横向占用，$P_k$ 为所有允许旋转中仍无法消除
的侧向端口接近 lane，$W$ 为取货口联合形成的严格前沿宽度。只有满足下式的层设计才能进入坐标
生成：

$$
B_k+P_k+T_k\le W.
$$

调度器优先安排与取货口直接绑定的源设备。若同一个最长路径层的 ready 分量合放后超过容量，
就保持有向图偏序并把剩余分量拆到后续层；这会把“六台源石粉碎机铺满 18 格”和独立的
种植/采种循环分成两个构造层。若连任一 ready 分量单独放置都不能满足不等式，则在产生设备坐标
和调用 A* 之前返回 `frontage-capacity` 诊断，其中包含 $B_k$、$P_k$、$T_k$、所需宽度和实际
前沿宽度。该证明使用乐观最小占用，因此只负责提前排除必然无解的层次；通过后仍必须接受实际
矩形逐行容量、端口分配和完整路由复核。

##### “俄罗斯方块”式增量顺序基线

复杂顺序基线不会先把全部设备静态排满后再一次性补带，而是把缩点 DAG 中的每个单设备分量或
循环 SCC 当成一个待落位块。完整物料图的生产者—消费者分配只计算一次；即使同层设备改变落位
先后，已分配的边也不能临时改接到另一个同类设备。第 $k$ 步只验证两端都已经落位的边集：

$$
E_k=\{(u,v)\in E\mid u\in V_k,\ v\in V_k\},
$$

其中 $E$ 是完整逐 lane 有向边集，$V_k$ 是当前已落位设备集合。

每个块从其所有前驱块下方开始，在取货口真实前沿宽度内向下试落。除最低合法位置外，还保留
$1$、$2$、$3$、$4$、$8$ 格的有限抬升回退；水平方向保留左、中、右三个落位带。同层互不依赖块分别尝试
拓扑稳定正序、逆序和两端交替顺序，避免三个策略因设备尺寸相同而退化成同一种排列。任何坐标
候选都必须满足：

$$
\begin{aligned}
x_i &\ge x_{\min},\\
x_i+w_i &\le x_{\max},\\
R_i\cap R_j &= \varnothing \qquad (i\ne j),
\end{aligned}
$$

其中 $[x_{\min},x_{\max})$ 是所有取货口联合形成的严格前沿，$R_i$ 是设备矩形。

设备矩形同时是传送带不可穿越的硬障碍。对于源设备位于当前层之前、目标设备位于当前层之后的
跳层物流边，当前层每一行都必须提前保留不少于其 lane 总数的空闲前沿格。即使下游设备尚未
落位、增量路由暂时看不到这些连接，铺满前沿形成“设备墙”的候选也会立即淘汰。这个前瞻规则
只保证逐行通道容量；真实端口、转弯、交叉和已有物流冲突仍由每次落块后的完整路由校验负责。

全局重排不能只统计“穿过当前层”的跳层边，还必须扣除本层设备端口已经占用的接近通道。对
任一候选截面 $r$，定义可供同方向传送带使用的空闲容量为 $C_r$，必须穿过截面的 lane 数为
$T_r$，因设备旋转和端口朝向而必须占用该截面的端口接近 lane 数为 $P_r$。进入完整寻路前必须
满足：

$$
T_r+P_r\le C_r.
$$

这里的 $P_r$ 不是设备矩形外观上“空出来”的宽度，而是源端和目标端口选定后必须保留的实际
接近带。交叉连接器最多允许一条南北线与一条东西线共享一个格子，不会增加两条同方向线路的
截面容量。

以“旋转研磨机并把种植/采种循环后置”的候选为例，局部截面只有旋转释放的两列，因此
$C_r=2$；两条“源石粉碎机到该研磨机”的输入 lane 已经要求 $P_r=2$；后置循环还需要至少一条
线路穿回研磨机组之前，即 $T_r=1$。于是：

$$
T_r+P_r=3>2=C_r.
$$

所以该候选是结构性无解，不应交给 A* 反复尝试。U 型方案虽然改变了设备外轮廓，但两个侧臂
各自释放的通道仍被对应研磨机的源石粉末输入占满；只要循环模块位于研磨机组之后，同样存在
至少一个违反上述不等式的截面。全局候选生成器必须先完成这项容量证明，再枚举坐标、端口和
布线顺序。

循环 SCC 的折叠模板不再假设循环恰好包含三个设备。构造器只根据兼容性有向图识别反馈角色，
再用已经冻结的实际分配边计算外送和旁路 lane；这样不会因为等价生产者已经满足需求、实际分配
省略一条兼容回边，就漏掉原本存在的循环结构。构造器根据图和 lane 需求枚举
环内最大扇出枢纽、所有有效外送出口和任意数量的回流成员：枢纽与回流成员组成可换行的相向
设备架，并同时保留边缘偏置与均衡走廊两类设备架；外送出口在设备架下一行落位，旁路 lane 数
约束横向通道容量而不再被错误换算成额外高度。多个枢纽或出口得分相同时会保留为
不同候选，每个 SCC 最多保留八种折叠角色；设备 ID 仅稳定遍历顺序，不负责选定唯一布局。多个
循环同时存在时采用“基础方案 + 单个 SCC 替换”的线性候选谱系，避免角色组合的笛卡尔积；通用
SCC 装箱始终作为最后一个候选。若子图并非强连通则不生成折叠候选。因而配方名、物料名、设备
定义和“三节点”数量都不参与模板选择。

每落入一个块就尝试路由 $E_k$。成功状态携带当前设备和传送带进入下一步；失败状态回滚该块，
改试其他横向带、抬升量或同层次序。但“前缀可路由”不等于“完整图可路由”：反馈 SCC 或尚有
未落位下游的扇出源会额外保留少量相同几何的冷布线状态，最终允许所有端口和线路一起重新分配。
已布线状态与冷布线状态交错进入完整验证，避免一次局部成功反而锁死后续支路。

候选束不仅按包围面积与空位排序，还按实际端口外侧格、逃逸方向和多输入设备的接近空间排序，并为循环 SCC 和具有两个
以上外部下游的扇出块保留独立的左、中、右“落位谱系”。这样不会因为前两条支路暂时可通，就
过早剪掉能为第三条支路保留出口的姿态。该阶段只负责构造严格遵守上下游和取货口宽度的可路由
基线；设备簇内移、传送带贴边、空洞压缩和轮廓优化仍在基线可行后执行。

若同层多个非取货口设备的总宽度已经占满前沿，它们会作为一个同步路由货架整体落位，在此前
所有层的最低边界之后统一保留端口走廊，不再让单台设备先落入上游空洞并堵住同层兄弟。对于
“多个上游汇入、没有后继”的终端，构造器会比较实际旋转端口；侧向进货口可行时把终端放到对应
前沿边界，使多条输入先组成水平汇流干线。两个规则只读取层宽、入度、出度和端口方向。

端口分配同样属于增量状态。一个设备的某条线路只能释放自己选中的源、目标端口；同设备尚未
使用的兄弟端口外侧格仍视为保留格，早铺线路不能把它当作捷径穿过。多输入和多输出设备分别
枚举源端镜像、目标端镜像、双端镜像和不镜像四种组合，避免把两侧端口顺序错误地绑定在一起。
若相邻设备的源、目标端口落在同一个外侧格，该零长度连接必须先完成并锁定该格，不能让较长
线路把它误当作公共通道。这能解决由端口占用顺序造成的假死锁；若多个连接在端口之外仍争用同一狭窄走廊，则进入后续
有界 rip-up/CBS 联合寻路，而不是继续扩大设备落位束。

完整布局可行后还会执行固定设备的物流质量邻域。算法先只拆除共享同一设备的扇入或扇出核心
线路，联合重选端口和铺设顺序；只有核心组无法改善时，才逐级加入与它相交、相邻的通道线路。
组外线路保持不动，候选必须继续满足取货口硬边界和全部物料流验证，并且只有完整目标向量严格
改善时才会替换原布局。

顺序基线分两张图查看：

- `headless graph` 在布局前导出设备实例有向图；列是 DAG 层，箭头标出物料和 lane 数，橙色边框

- `headless optimize --svg` 导出实际设备、端口和传送带铺设图。顺序模式默认执行硬前沿约束；
  只有请求明确设置 `frontageConstraint: "soft"` 时才输出带溢出指标的诊断图，不能把它作为正式
  可行布局。

#### 阶段七：可选 CP-SAT 布局候选

启用 `search.cpSat.enabled` 后，Python OR-Tools CP-SAT 会生成初始约束布局，并在后续额外精炼
轮次中承担一次有界全局重建。模型保证设备位于
区域内且互不重叠，正确处理长方形设备旋转后的宽高，并约束每台设备保留足够的实际输入输出
端口。目标函数近似压缩包围盒、最长边、物料流距离和错误端口朝向，同时让共同终端和共享上游
保持接近。CP-SAT 只生成设备布局，不能证明传送带或管道一定可铺；每个结果仍须经过完整 A*
验证。`maxSeconds` 同时约束候选建模和求解，所有变体共享该预算；达到截止时间后不再启动后续
候选。Python、OR-Tools 不可用、超时或无解时会记录状态，并自动回退到确定性 LNS。

##### CP-SAT 路由感知数学模型

模型求解的是设备矩形位置和旋转，不直接为每条传送带建立逐格流变量。定义：

| 符号 | 含义 |
|---|---|
| $D$ | 参与布局的生产设备和协议存储箱集合 |
| $F$ | 保持当前位置的设备集合，通常是部分重建销毁集之外的设备 |
| $O$ | 仓库卸货口、仓库总线等固定障碍集合 |
| $E$ | 生产规划产生的有向物料边集合 |
| $P_i^{\mathrm{in}}, P_i^{\mathrm{out}}$ | 设备 $i$ 在不同旋转下可用的实际输入/输出端口 |
| $L_e$ | 物料边 $e$ 按真实吞吐拆分后的 lane 数 |
| $c_e$ | 物料边 $e$ 的流量权重 |
| $W,H$ | 用户请求的布局区域宽度和高度 |

主要决策变量如下：

$$
\begin{aligned}
x_i,y_i &\in \mathbb{Z}_{\ge 0}
&& \text{设备 }i\text{ 的左上角坐标},\\
r_i &\in \{0^\circ,90^\circ,180^\circ,270^\circ\}
&& \text{设备旋转},\\
w_i,h_i &\in \mathbb{Z}_{>0}
&& \text{旋转后的宽高},\\
X_i &= x_i+w_i,\qquad Y_i=y_i+h_i
&& \text{设备右边界与下边界},\\
a_{i,p,r} &\in \{0,1\}
&& \text{端口 }p\text{ 在旋转 }r\text{ 下是否具有完整逃逸走廊},\\
B_x,B_y &\in \mathbb{Z}_{>0}
&& \text{整体使用宽度和高度},\\
A &= B_xB_y
&& \text{包围面积},\\
s_e &\in \mathbb{Z}_{\ge 0}
&& \text{物料边 }e\text{ 的走廊间距缺口},\\
z_{i,k} &\in \{0,1\}
&& \text{设备 }i\text{ 是否保持失败布局 }k\text{ 中的姿态}.
\end{aligned}
$$

设备旋转与尺寸通过允许表关联：

$$
(r_i,w_i,h_i)\in
\left\{
\begin{aligned}
&(0^\circ,\bar w_i,\bar h_i),\\
&(90^\circ,\bar h_i,\bar w_i),\\
&(180^\circ,\bar w_i,\bar h_i),\\
&(270^\circ,\bar h_i,\bar w_i)
\end{aligned}
\right\},
$$

其中 $\bar w_i,\bar h_i$ 是设备未旋转时的尺寸。

模型包含以下硬约束。

1. 区域边界：

$$
0\le x_i,\qquad
0\le y_i,\qquad
X_i=x_i+w_i\le W,\qquad
Y_i=y_i+h_i\le H,
\qquad \forall i\in D.
$$

2. 设备与固定障碍不重叠：

$$
\operatorname{NoOverlap2D}
\left(
\left\{[x_i,X_i)\times[y_i,Y_i)\mid i\in D\right\}\cup O
\right).
$$

3. 部分重建锚定。未进入销毁集的设备保持原姿态：

$$
x_i=x_i^{\mathrm{inc}},\qquad
y_i=y_i^{\mathrm{inc}},\qquad
r_i=r_i^{\mathrm{inc}},
\qquad \forall i\in F.
$$

4. 端口逃逸走廊。端口外侧第一格不能只是在设备外，还必须沿端口法向连续保留若干格。单 lane
使用两格，多 lane 使用三格：

$$
\delta_{i,d}=
\begin{cases}
2,&q_{i,d}=1,\\
3,&q_{i,d}>1,
\end{cases}
\qquad d\in\{\mathrm{in},\mathrm{out}\},
$$

其中 $q_{i,d}$ 是方向 $d$ 所需的 lane 数，$\delta_{i,d}$ 是逃逸深度。设
$\mathbf{o}_{i,p,r}$ 为端口外侧第一格，$\mathbf{n}_{i,p,r}$ 为端口朝外的单位法向量，则：

$$
a_{i,p,r}=1
\Longrightarrow
\begin{cases}
r_i=r,\\
\mathbf{q}_{i,p,r,t}
  =\mathbf{o}_{i,p,r}+t\mathbf{n}_{i,p,r},\\
0\le q^x_{i,p,r,t}<W,\\
0\le q^y_{i,p,r,t}<H,\\
\mathbf{q}_{i,p,r,t}\notin R_j,
  &\forall j\in D\setminus\{i\},\\
\mathbf{q}_{i,p,r,t}\notin O,
\end{cases}
\quad
\forall t\in\{0,\ldots,\delta_{i,d}-1\}.
$$

每个方向必须提供足够数量的独立端口：

$$
\sum_{p\in P_i^d}\sum_r a_{i,p,r}\ge q_{i,d},
\qquad
\forall i\in D,\quad
d\in\{\mathrm{in},\mathrm{out}\}.
$$

这条约束同时禁止端口朝向地图外侧，解决了旧模型可能生成 $x=-1$ 或 $y=-1$ 路由端点的问题。

5. 流边走廊缺口。先计算两个设备矩形在水平和垂直方向上的非负间距：

对于物料边 $e=(u,v)$：

$$
g_e^x=
\max\left\{
x_v-X_u,\;
x_u-X_v,\;
0
\right\},
$$

$$
g_e^y=
\max\left\{
y_v-Y_u,\;
y_u-Y_v,\;
0
\right\},
$$

$$
g_e=g_e^x+g_e^y,\qquad
\hat g_e=\min\{2,\max\{1,L_e\}\},\qquad
s_e=\max\{0,\hat g_e-g_e\}.
$$

$s_e$ 是软缺口而非硬不可行条件：复杂线路仍可绕行，但求解器会优先为多 lane 连接保留两格接近
空间。fan-in/fan-out 流簇允许最近设备间距不超过两格，以免与该走廊目标互相矛盾。

6. 候选多样性 no-good 割。若布局 $k$ 已经生成，则下一变体不能完全重复它：

$$
z_{i,k}=1
\Longleftrightarrow
\left(
x_i=x_{i,k}\land
y_i=y_{i,k}\land
r_i=r_{i,k}
\right),
$$

$$
\sum_{i\in D_k}z_{i,k}\le |D_k|-1.
$$

目标函数是最终词典序目标的可求解代理。实际实现使用下列有界整数权重：

$$
\begin{aligned}
\min\quad
&1{,}000{,}000A
+20{,}000\max\{B_x,B_y\}\\
&+100{,}000\lambda
  \sum_{e\in E}c_es_e\\
&+5{,}000\lambda
  \sum_{c\in C}g_c\\
&+w_d\lambda
  \sum_{e\in E}c_ed_e\\
&+4w_d\lambda
  \sum_{e\in E}\rho_e\\
&+2{,}000d_{\mathrm{div}}
+w_xB_x+w_yB_y.
\end{aligned}
$$

其中 $\lambda$ 是物流目标缩放系数，$g_c$ 是流簇间距，$d_e$ 是设备中心曼哈顿距离，
$\rho_e$ 是端口朝向惩罚，$d_{\mathrm{div}}$ 是候选多样性距离。距离权重 $w_d$ 按候选变体在
$80/240/480/160$ 间轮换，宽高偏置 $w_x,w_y$ 也随变体变化，用来生成
不同形状的候选。该加权式只是 CP-SAT 的廉价代理，不宣称与最终词典序目标完全等价；候选仍由
完整 A* 和物理拓扑验收后，按照正式词典序目标决定胜负。

A* 失败首先形成普通诊断证据，其中已铺物流前沿只用于拆线顺序、失败边优先级和 LNS 热点，不能
直接成为 Master 的硬约束。只有 producer/consumer lane 分配已冻结时，Router 才在忽略已铺物流、
端口预留、转弯代价和路由顺序的设备障碍网格上生成两类完备证书：第一类枚举失败 lane 的全部
合法端口，证明它们仍被静态自由空间割集分离（或当前姿态没有合法端口）；第二类先扫描每条完整
横向或纵向割面 $\Gamma$，仅把全部合法起点与终点确定落在割面两侧的 lane 计入 $D_\Gamma$，并以
割面两侧均无设备/前沿障碍的网格边数作为上界 $C_\Gamma$。若

$$
D_\Gamma>C_\Gamma,
$$

即生成 static cut-capacity certificate。若所有直线割都不能证明失败，Router 再以失败 lane 优先、
最多 8 组不同端点集合为种子，在至多 4096 个格子的静态自由空间上运行单位边容量 max-flow/min-cut。
残量源侧集合 $S$ 的完整边界

$$
\delta(S)=\{(u,v)\mid u\in S,\ v\notin S,\ \{u,v\}\in A\}
$$

可以是 L 形、U 形或包围局部端口的任意形状。只有全部合法源端点位于同一侧、全部合法目标端点
位于另一侧的 lane 才计入该割需求；再次满足 $D_{\delta(S)}>C_{\delta(S)}$ 时，生成
static-general-cut-capacity certificate。种子枚举是有界且不完备的，但每个实际生成的证书都记录
完整网格划分边界，因此证明本身是完备且可复核的。边界端点或跨越两侧的可选端口不会计入需求，
所以该判断宁可漏报，也不会把端口选择或路由顺序造成的拥堵误报成布局不可行；使用裁剪搜索高度
的临时 Router 也无权生成硬证书。

容量证书除生成精确姿态 no-good 外，还以最多 8 条广义约束进入后续 CP-SAT。直线割也先展开成
显式相邻网格边，使轴向割与任意 min-cut 共用同一个模型。若所有必经 lane 的可移动端点仍保持
证书姿态，则 Master 必须满足：

$$
\sum_{g\in\Gamma} free_g(P)\ge D_\Gamma.
$$

其中 $free_g$ 为 Boolean，取 1 时割边两侧的格子必须同时位于所有可移动矩形和固定障碍之外。
所以只移动一个阻挡设备但仍未释放足够通道不会通过 Master；任一端点改变姿态后，该条件约束自动
解除，由新端口位置重新证明需求。

姿态 no-good 不再无条件包含割边上的所有阻挡设备。设割边总数为 $M$、需求为 $D$，固定障碍已经
保证阻断 $F$ 条边；只需选择一组可移动阻挡设备 $B'$，使其覆盖的不同割边满足

$$
F+\left|\bigcup_{i\in B'} blockedEdges_i\right|\ge M-D+1,
$$

就足以继续证明剩余容量至多为 $D-1$。阻挡候选不超过 16 台时用迭代加深求最小基数集合，更大
冲突用确定性删除得到 inclusion-minimal 集合；lane 端点姿态仍全部保留。这样 conflict cut 只要求
真正维持容量不足的设备之一改变，而不会因同一割上的冗余阻挡扩大销毁邻域。

证书记录所有必经 lane 的可移动端点以及收缩后仍足以维持容量不足的割边阻挡设备，保存它们在失败候选中的
$(x_i,y_i,r_i)$。下一轮优先把这些设备加入部分销毁集，并增加：

$$
\sum_{i\in D_{\mathrm{cert}}}
z_{i,\mathrm{cert}}
\le
|D_{\mathrm{cert}}|-1.
$$

因此至少一台经证明相关的设备必须离开失败姿态。失败修复 CP-SAT 会立即带着该 cut 重求解，
证书也会保留给后续全局重建；精确姿态证书最多保留 64 个。若 lane 分配可变，或静态松弛仍连通且
有界轴向/通用割搜索都没有容量证明，则失败可能来自物流占用、贪心端口分配或路由顺序，此时不会
生成硬 cut，而只继续启发式回溯。

因此整体是有界分解求解：

目标归因与部分销毁 → CP-SAT 设备布局 → 端口漏斗 → 完整 A* 路由。成功候选进入精英档案并按
词典序比较；只有携带 connectivity/capacity certificate 的失败候选才生成姿态 no-good 割并反馈
下一轮。

没有直接采用逐格多商品流模型，是因为它需要为每条物料边、每个地图格和每个方向建立近似
$O(4|E|WH)$ 个流变量，再叠加端口、转弯、交叉与不同物流类型互斥约束。当前分解模型
把 CP-SAT 保持在秒级预算内，并让 A* 继续作为真实可铺设性的权威判定。

#### 阶段八：附加仓储设施并铺设物流

协议存储箱从启发式初始打包开始就和生产设备一起参与局部布局，不再事后固定到 $y=0$。仓储侧以
取货口为固定局部锚点：生产设备和协议存储箱可以移动，仓库总线的位置由取货口派生。单取货口
同样形成有效前沿宽度；当设备宽度允许且纵向层布局无碰撞时，整条物流链先对齐到取货口前沿。
随后建立障碍网格并开始端口感知路由。
同一布局会尝试多种连接顺序，包括端口受限优先、长线优先、短线优先、内部连接优先、仓库供料
优先、产品入库优先、一对多 fan-out 骨架优先和多对一 fan-in 骨架优先。对于一对多或多对一
结构，端口还会按生产者和消费者的空间次序配对，减少交叉。

每条连接枚举尚未使用的实际输入输出端口，并对端口对执行轮廓感知 A*。令 $v$ 为下一格，
$d$ 为进入方向，$D(v)$ 为该格到生产设备、仓储设施或已铺物流格的曼哈顿距离，当前物理布局
的轴对齐包围盒为 $B$。单步代价为：

$$
c(v,d)=
1
+2\,\mathbb{I}[d\ne d_{\mathrm{prev}}]
+6\,\mathbb{I}[v\text{ 为合法交叉}]
+\min\!\left(3,\max(0,D(v)-1)\right)
+2\,\mathbb{I}[v\notin B].
$$

因此紧邻设备或已有传送带的格子满足 $D(v)=1$，不产生间隙惩罚；离外围越远、或继续向当前包围盒
外扩张，代价越高。该代价仍保留有限惩罚，所以端口可达性、避障和连接成功始终优先，不会把贴边
偏好误当成硬约束。

对于不同端口对得到的完整路径 $P$，再按下式作词典序比较：

$$
\left(
A_{\mathrm{bbox}}(S\cup P),
A_{\mathrm{hull}}(S\cup P),
\sum_{v\in P}\max(0,D(v)-1),
|P|,
T(P)
\right),
$$

其中 $S$ 包含全部设备格和此前已经铺设的物流格，$A_{\mathrm{hull}}$ 对 $S\cup P$ 中每个单位格
的四个角点取凸包。因此传送带明确计入候选路径的外接矩形与凸包，而不是只在最终报告阶段计入。
$T(P)$ 是转弯数。这样可阻止“路径略短但把外轮廓撑大”的端口选择，同时避免用额外蛇形传送带
伪造更好的空位指标。

固体只能与固体、液体只能与液体形成合法垂直交叉；成功交叉时自动升级为项目原生跨线连接器。

若线路失败，优化器会保存失败物品、来源与目标、尝试过的端口对、来源可达格和搜索前沿阻挡物。
这些信息既进入报告，也用于后续移动实际阻挡设备，而不是只返回一条无法布线的错误。

#### 阶段九：自动放置供电扩散器

物流成功后，优化器枚举所有不与设备或物流重叠、且至少覆盖一台需电设备的供电桩位置。设需电
设备集合为 $D$，候选位置集合为 $P$；若位置 $p$ 的 12 格供电范围与设备 $i$ 的矩形相交，记
$a_{ip}=1$。第一步精确求解：

$$
N_{\mathrm{power}}^{\min}=\min\sum_{p\in P}x_p,
$$

$$
\sum_{p\in P}a_{ip}x_p\ge1\quad(\forall i\in D),
\qquad
x_p+x_q\le1\quad(\forall p,q\text{ 的 }2\times2\text{ 占地重叠}).
$$

求解器使用按供电桩数量递增的精确分支定界；第一次得到完整覆盖即证明最小数量，不再受旧实现
“最多 8 个供电桩、48 个 beam 状态、每种覆盖保留 12 个位置”的近似限制。随后只在
$\sum x_p=N_{\mathrm{power}}^{\min}$ 的方案中比较前沿溢出、包围盒、轮廓、空洞和贴边程度；几何
beam 若漏掉该数量的方案，会回退到精确求解留下的放置见证。所有声明 `requiresPower` 的设备
（包括协议存储箱）都必须被覆盖，否则候选淘汰。报告中的 `minimumPowerDeviceCount` 是证明值，
并应与实际 `powerDeviceCount` 相等。

这里的最小值针对一份已经完成设备摆放和物料布线的固定布局计算。供电桩属于后置、低优先级
设施：它不会参与此前的传送带寻路，也不会为了少一根供电桩主动推翻更紧凑的物料布局；但补入
后的供电桩仍计入最终面积并遵守取货口宽度。若某个已布线候选不存在完整覆盖位置，该候选会被
淘汰并由正常布局搜索尝试下一种几何；只有所有已成功布线的候选都无法供电时才报告供电可行性
失败，而不是在第一个失败候选上中止整个搜索。

#### 阶段十：按字典序评价候选

完整候选按以下优先级逐项比较，而不是把所有指标加权求和：

1. 硬约束违规数；
2. 仓库卸货前沿溢出格数；
3. 计费包围盒面积；
4. 凸包轮廓面积；
5. 转弯与交叉数量；
6. 物流设施格数；
7. 凸包轮廓内空位；
8. 封闭空洞格数；
9. 包围盒空白格数；
10. 最长边；
11. 固定物料布局完全供电所需的最少供电桩数。

只要高优先级指标更好，低优先级指标就不能反超。协议存储箱、产品入库传送带、生产设备和仓储
设施计入占地；仓库取货口到生产设备的外部供料带完整生成并验证，但标记为不参与计费面积。
报告同时给出计费占地和包含免费供料带的完整物理占地。凸包轮廓及其轮廓内空位始终按完整物理
布局计算，包含所有传送带、管道和设备；免费供料带只影响计费口径，不会从几何轮廓中消失。

#### 阶段十一：LNS 局部破坏与修复

得到可路由基准后，优化器会执行若干轮局部优化，包括单台设备平移和旋转、fan-out 生产者搬迁、
多生产者与存储箱联合搬迁、整个流簇平移、边界设备回溯、空位检测、ejection chain、相关设备
交换以及可选的局部 CP-SAT 修复。便宜的几何与端口指标先过滤候选，再按操作族保留多样性；
单设备平移现在同时覆盖生产设备和协议存储箱，且候选束优先保留存储箱平移与生产设备平移，
不会再被后续簇修复或全局候选挤出预算。便宜候选按取货口溢出、设备包围面积、凸包轮廓面积、
封闭空洞和包围盒空格依次比较。
当 `search.scope = local` 时，本段启用生产设备/协议存储箱的三格内平移和旋转、循环 SCC
刚性平移、循环内部改形，以及“直接生产者 + 协议存储箱”终端簇整体平移；独立 fan-out 重排、
设备交换、ejection chain、CP-SAT 和全局重建仍全部关闭。循环内部改形依据当前实际分配的
生产者—消费者连接求强连通核心，并纳入与核心直接相连的生产设备，不按配方名或设备 ID 写死。
每个成员可独立平移、对角错位或旋转，探索距离按近距（不超过四格）、中距（五至六格）和极限
（七至八格）分层；候选束先保证每个成员至少获得一次完整布线机会，再尝试更深压缩。便宜排序
同时考察实际端口方向/可用走廊、循环邻域包围盒和流距离；邻域跨度也是供电覆盖的代理，成功
布线后仍会重新执行真实供电扩散器集合覆盖。因此既能完成研磨机行与协议存储箱整体上移，也能
在下一轮改变种植机—采种机循环内部形状，同时避免局部检查意外演变成全图重建。
循环核心的刚性移动使用已经选定的实际物流边再次求强连通分量，并向真实外部后继靠拢；这与仅按
“产物类型可能连接”推断的宽松 SCC 分开处理，避免把没有参与回流的第二台种植机误并入刚性组。
同面积、同轮廓的候选先比较转弯与交叉，再比较传送带格数：上游设备移动即使暂时没有缩小包围盒，
只要把曲折线路整理为可压缩直带，也能作为下一轮的有效正反馈。

每轮局部布线完成后，优化器会沿两个轴扫描物流：不含生产/仓储设备、线路端点、转弯或交叉，
且只被垂直直带穿过的行是安全水平切面；只被水平直带穿过的列是安全垂直切面。删除行时，下方
全部生产设备和协议存储箱整体上移；删除列时，右侧设备后缀整体左移。对于单条已经证明安全的
切面，优化器直接收缩现有路径：后缀内线路随设备平移，跨切面线路删除一个垂直于切面的直带格，
端口和连接顺序保持不变；只有收缩后发生碰撞、断点或非法重叠的线路才进入有界拆线修复。随后仍
执行硬前沿、吞吐、连通和供电覆盖验收，因此路径证明只消除了不必要的全量 A*，没有绕过可行性。
这一“已证明切面规范化”在 `scope=local` 时即使 `iterations=0` 也会收敛执行，因为它不枚举
新设备排列或端口方案。普通局部邻域仍可对同一几何执行完整重布线，与既有质量搜索空间保持一致。
水平占地跨度从取货口前沿开始计算，仓库基段不再把统计宽度从 $18$ 格扩张到 $24$ 格；基段仍
参与蓝图连接和渲染，不参与凸包、空位面积或设备面积。高度继续以布局原点为基准，仓库外壳实际
占用的纵向空间不能从请求高度中静默扣除。若取货口及其后的实际产线跨度没有缩小，候选
才会在布线前淘汰；这类移动属于普通坐标优化，不应冒充消行并消耗完整 A* 预算。
同一轴发现多个安全切面时，除单切面候选外还会生成一次删除该轴全部安全线的“俄罗斯方块式”
候选；水平和垂直切面仍分两次验收，避免一个轴的移动使另一个轴原有的安全证明失效。
常规局部候选束结束后进入统一的“局部收敛闭包”，不再给切带、设备移动和布线精修分别指定互不
相关的固定轮数。每次完整闭包依次执行：已证明直带切面规范化、保留既有路径的推测性切带、同一
设备几何的冷启动端口/路由变体、一次上游设备移动、一次固定设备端口/路由精修；下一轮重新从直带规范化
开始。只有完整一轮没有任何严格词典序目标改善时才以 `fixed-point` 结束。每次接受的状态都严格优于
当前状态，且整数搜索框的宽高之和提供确定性的安全轮数上界，因此不会在等价布局间循环。

推测性切面压缩不要求切面上的现有传送带已经全部笔直，而是选择无设备的水平或垂直切面，将切面
之后的全部生产设备和协议存储箱作为一个刚性后缀向原点方向移动一至三格。它先收缩仍然有效的旧
路径；随后同一设备几何仍重新选择端口并完整布线参与质量比较。两个轴共享最多八个候选的总束，并在轴之间轮转抽样，
既不会让单轴候选挤掉另一轴，也不会因为轴向泛化无界增加布线次数。候选不仅可以凭面积缩小胜出，
同面积下轮廓、空洞、转弯、交叉或带长的严格改善也会继续闭包。

切带达到当前固定点后，优化器执行一轮“上游设备行”搜索。设备行按垂直占地
区间是否重叠来识别，而不是要求设备同高且具有完全相同的 $y$ 坐标；因此同排的 $5\times5$
种植机和 $3\times3$ 粉碎机属于同一高度带，粉碎机可以在五格高度范围内上下滑动。候选包括
单设备左右移动、旋转、矮设备的带内滑动，以及整行保持相对形状的刚性左右平移。候选生成和
受影响线路重布阶段不放供电桩，物流成功后才重新求解供电覆盖并用完整目标验收；补入的供电桩
计入面积、轮廓和硬前沿，协议存储箱等所有 `requiresPower` 设备也必须被覆盖。该阶段必须在
消行之后运行，保证线路更短、转弯更少的 $41$ 行中间解不能取代已经得到的 $40$ 行布局。
若某一行只有一台生产设备，但它接收其他生产设备的内部物料并直接向协议存储箱输出，则该设备
也是通用终端行。固定点阶段会额外尝试整台设备向上或向下一格；成功后下一轮重新生成候选，因此
连续两格压缩由两个分别验证的单步组成，协议存储箱保持固定。该规则只读取有向物流邻接关系，
不读取设备或配方名称。
同行设备不做所有位置的笛卡尔积枚举。候选束优先保留高低设备混排行，以及内部存在双向连接的
循环行；每次只接受一个严格改善完整目标的坐标移动。一次移动成功后立即重新执行推测性消行，
锁定新面积再生成下一个设备的候选，形成“设备坐标下降—后缀消行”的交替优化。这样上方种植机
向左移动所释放的两行会先被压缩，采种机随后向右移动只能在不破坏该面积的前提下胜出，避免
低交叉但更高的中间布局覆盖已经发现的紧凑解。
每次设备移动或路由精修后，闭包都会重新执行“保留路径的轴向切带折叠”。水平切带删除竖向跨度并上移
下方设备，垂直切带删除横向跨度并左移右侧设备；两个端点都在后缀内的线路随设备整体平移，
跨越切带的线路只折叠带内跨度并保留切带外已有的转弯。折叠后若某条线路撞到设备、产生断点、
同轴重叠或非法交叉，只拆除这些失效线路并重新寻路，其余线路原样保留，最后仍执行完整物流、
前沿、吞吐和供电验收。候选束按设备后缀轮转抽样，并保留同一后缀的一格、两格和三格移动，
避免“一格改善不足、三格不可行”时漏掉恰好可行的两格压缩。
上述局部过程由固定的 `LOCAL_COMPACTION_POLICY` 约束：切带距离最多三格、切带候选束最多八个、
每个切带几何按至少六种路由变体继续尝试到首次完整可行；每轮上游移动最多验证十二个候选，并为
每个移动安排至少八种路由变体。首次可行后的剩余变体沿用既有局部质量基准的终止规则，并由每轮
固定设备几何的布线精修补充端口质量。闭包轮数不属于经验策略参数：只要仍有严格改善就继续，只有
达到宽高和安全上界时才报告 `safety-bound` 而不能声称收敛。局部面积压缩候选
保留二十次拆线扩张和八个失败优先级预算，避免最后一两条线路失败时过早放弃能够缩小外接矩形
的设备布局。
这些参数只描述设备矩形、端口、已路由路径和物料有向图；候选生成不得读取配方名、物品名或自动
生成的设备 ID。`scope=local` 只允许保持拓扑层次和设备银行成员关系的移动、旋转、刚性簇平移及
切带折叠，不允许交换上下游层、任意重排设备银行或销毁全部设备重建。改变该策略即视为改变局部
基准，必须同时通过通用重命名不变性测试、双轴直带测试、直接端口桥测试、切带转弯测试和正式
示例回归后才能接受。局部拆线重布还以“当前拆线集合 + 失败连接优先级顺序”作为状态键；两者都
没有变化时立即停止，只有优先级确实改变才允许在完全拆线状态继续尝试，避免重复消耗二十次预算。
当保留式重布已经拆除全部旧线路时，该次调用在语义上等同于同一几何、同一路由变体和同一优先级
顺序的冷启动重布。优化器会保存这个确定性失败；后续冷启动回退遇到完全相同的顺序时直接复用失败
并提升失败连接，不再重复执行 A*。未尝试过的空优先级和后续顺序仍按原次序运行，因此缓存只消除
等价状态，不缩减端口方案。对于明确的直带消行、推测性切带和路径折叠候选，还会先计算仅由生产
设备矩形决定的面积下界；若该下界已经严格大于当前完整布局面积，则传送带和供电只可能继续扩大
矩形，候选会在路由前被安全淘汰。每次固定设备布局开始布线时，还会在仅包含设备硬障碍的宽松
网格上计算一次连通分量并由所有连接复用；宽松网格允许穿越已有物流且暂不考虑转弯、交叉和
保留端口，因此若两个端口在这里仍不连通，严格 A* 必然失败，可直接跳过该端口对而不会漏解。
若一条连接的两个端口外侧格重合，整条连接只包含一个传送带格，该格被显式标记为“直接端口桥”：
即使同一行或列的其他线路都是直带，也禁止删除该切面，避免把取货口—粉碎机等本来直接相接的
设备分开。推测性切面同样检查桥两端：若切面会把直接桥的两个设备分到移动侧与固定侧，整个候选
直接禁用。

对于位于生产者银行下方的协议存储箱，终端邻域还会生成通用“下角侧挂”候选：存储箱旋转后放到
生产者银行左下角或右下角，三条输入线在银行下方分流，并且整个候选严格留在取货口前沿内。
同排侧挂会保留三列扇入通道，但只有满足硬前沿的候选才能进入最终比较。终端压缩候选还把
A* 可用高度限制到新设备底边外一格，禁止传送带从原始大画布底部绕行后把外接矩形重新撑高。
`search.refinementCandidates` 控制每个阶段真正进入完整路由验证的候选数。初始阶段会先保留
确定性基线，再在仓库专项、CP-SAT 和普通启发式候选之间轮转；当 `iterations=0` 且已有可行
基线时，启发式设备布局精炼完全关闭，只保留端口与传送带优化，以及不改变端口和拓扑的已证明
直带切面规范化。本地模式中，`iterations=1～16`
执行一轮布局精炼，`17～32` 执行两轮，`33～48` 执行三轮，`49～64` 执行四轮，
`65～80` 执行五轮。若初始快速束全部失败，则确定性地追加最多 8 个未见候选；
`search.refinementCandidates` 限制普通初始候选和常规布局精炼，不削减固定局部压缩策略的
八个切带候选、十二个上游移动候选及其既定路由变体序列。只要 `iterations>0`，这些质量下限以及
统一的局部收敛闭包都会执行；低预算只减少闭包之前的普通候选探索，
不能把局部压缩从完整搜索悄悄降级为近似搜索。
仍失败时按已完成连接数选出最深的 4 个失败布局，将路由顺序上限增加 2（总上限仍为 9）。
顺序基线构造器已经随候选生成一套完整增量路由；优化器先用这些可行见证对候选排序，再为每个
顺序种子执行全部请求的冷启动路由变体。该两阶段只改变执行顺序，不删除任何种子几何或路由
变体。二次评估严格记住增量种子所属的原始变体，不会把“第一个尚未尝试的冷变体”误判为种子
并重复使用旧线路。
报告通过 `adaptiveCandidatesEvaluated`、`adaptiveRoutingAttempts` 和
`effectiveRoutingVariants` 区分正常搜索与这段有界恢复开销。搜索效率可通过
`routingVariantAttempts`、`localAreaLowerBoundRejected`、`localRepairAttempts`、
`localFullRerouteAttempts`、`localFullRipFailureStatesReused`、`localConvergencePasses`、
`localConvergenceTransitions`、`localConvergenceStoppedBy` 和
`localRoutingVariantsSkippedAfterSuccess`、`relaxedConnectivityRejectedPortPairs`
以及 `seededInitialCandidatesRanked`、`seededInitialCandidatesPolished`、
`seededInitialColdVariantsSkipped` 直接审计：它们分别记录实际开始的变体、面积下界
淘汰数、局部保留式调用数、真实冷启动次数、被缓存消除的等价冷启动次数、闭包完整轮数、接受的
严格改善次数、闭包停止原因、固定几何首次可行后省略的剩余变体数、宽松连通性在 A* 前淘汰的
端口对数，以及顺序种子参与初排、完整冷路由精炼
和省略冷变体的数量。在质量优先模式下，`seededInitialCandidatesPolished` 应等于
`seededInitialCandidatesRanked`，`seededInitialColdVariantsSkipped` 应为 $0$。

效率优化必须遵守“相对既定质量基准不缩减候选解集合”的质量优先原则：允许提前淘汰具有严格
数学下界证明的劣解，允许复用完全相同状态的确定性失败，也允许用可行性的必要条件跳过必败
端口对；不允许仅因运行时间较长就在既有策略之上进一步减少切带几何、设备移动组合、端口方案、
路由变体或局部修复深度。正式性能回归必须使用相同请求、相同随机种子和相同搜索预算；只有布局
目标向量不劣于基准时，耗时下降才计为有效提速。

完整路由且满足硬约束的候选不会只保留一个获胜解，而会进入最多 8 个状态的可行精英档案。
档案一半容量保留词典序目标最好的状态，另一半使用最远点采样保留设备位置和旋转差异最大的状态，
避免多个近似解占满档案；`eliteArchiveMaxDistance` 给出档案当前覆盖跨度。第一轮精炼仍只从当前
最优解出发，以保持原有快速路径；非局部搜索第二轮起最多选择 3 个几何差异较大的精英状态。
`scope=local` 的所有轮次只沿当前最优解继续压缩，避免本应留给全局优化的布局盆地切换分走局部
预算。软约束搜索需将 `iterations` 设为大于 16 才会进入第二轮。每轮完整 A* 候选总预算上限仍为
`search.refinementCandidates`（硬前沿可行解为原有的至少 12 个），当前最优解取得向上取整的一半，
其余精英平分剩余预算。因此全局探索能力来自预算重分配，不是无界增加路由次数。报告中的
`eliteStatesRetained` 和 `alternativeRefinementBasesUsed` 分别记录最终保留的可行精英数，以及
第二轮后实际使用过的非获胜精炼基线数。

启用 `search.cpSat.enabled` 后，每个额外精炼轮次还会从当前最优解执行一次归因式全局重建。
优化器按仓库前沿溢出、移除设备后的包围面积下降、封闭空洞邻接数和已路由路径代价依次定位热点，
选择约 40%（最多 8 台）的生产设备/协议存储箱；热点的下游消费者或存储终端优先成组加入，避免
固定终端割裂待重建物流。CP-SAT 只销毁这组设备，其他生产设备、仓库卸货口和总线保持固定。

当总预算至少 0.2 秒且候选数至少为 2 时，同一批次把约 80% 时间和 75% 候选分给部分重建，
其余留给销毁全部可移动设备的兜底；两者合计仍不超过 1 秒、6 个变体，并共同占用原有完整 A*
候选配额。所有重建候选清空旧线路，并尝试请求的全部 `routingVariants` 后才参与词典序比较。
`globalRebuildCandidatesGenerated/Routed/Improved` 报告整批结果，
`partialRebuildCandidatesGenerated/Routed/Improved` 单独报告部分重建路径；
`objectiveHotspotDeviceIds` 列出热点种子及随其加入的直接流邻居，
`globalRebuildCpSatElapsedMs` 报告额外求解时间。
全局候选被 A* 拒绝时，普通前沿证据继续驱动回溯与 LNS；只有冻结 lane 图上的设备障碍静态
连通性证明或显式网格边割容量证明失败时，其端点和经收缩仍必要的割边阻挡设备才生成姿态 no-good 割。
若还有后续精炼轮次，这些设备先进入销毁集，且 CP-SAT 必须改变至少一个证书姿态。
`certifiedRouteFailureCutsLearned` 报告实际学到的不同姿态 cut 数量，
`certifiedRouteCapacityCutsLearned` 报告保留的广义容量不等式数量。

设备只发生局部移动时，系统会找出起终点受影响、穿过新旧设备占地或与受影响线路交叉的最小
连接集合，优先保留其他旧线路，只拆除冲突线路并局部重布。局部修复失败后才退回完整重布线。
若紧凑布局只在最后一两条线路失败，失败连接会在下一次完整路由中获得更高优先级，以有限深度
实现“先铺最容易被堵死的线路”的回溯。若拆线集合已经扩展到全部连接，但新顺序曾达到
$21/22$，终端修复会在固定上限内继续使用最新失败边调整顺序，而不是在最接近成功时立即退出。

设备位置固定后的物流优化同时保留四类重布线邻域：释放实际交叉线的冲突邻域、同一设备向多个
后继供料的扇出邻域、多个前驱汇入同一设备的扇入邻域，以及相邻同型多输入设备组成的完整设备
银行。设备银行会一次释放全部入料线，先按“路径长度减端点曼哈顿距离”定位总绕行量最大的目标，
再枚举该目标最多四个进货口的精确分配；其余目标暂时固定在原端口，防止局部试验无关地扰乱整个
银行。这使端口选择从逐线贪心提升为一个有界的联合匹配问题，而不依赖配方名或设备 ID。
常规端口对先比较包围盒和轮廓，再比较与既有线路的真实交叉数和转弯数；设备银行释放后则先比较
交叉、实际路径长度和转弯，避免远端口仅因轮廓相同而击败近端口。所有线路候选完成以后才执行
供电扩散器集合覆盖，因此供电桩不会作为传送带寻路障碍；补入供电后的完整面积、轮廓、硬前沿
和所有需电设备（包括协议存储箱）的覆盖结果仍参与最终验收。

占地宽度现已排除仓库基段，并按六个取货口组成的 $18$ 格前沿统计；高度仍从布局原点计量。

新的第二阶段不再继续挤压已经拥堵的“六台源石粉碎机 + 砂叶粉碎机 → 三台研磨机”扇入走廊，

最后一轮又同时识别并删除了 $y=14$ 与 $y=23$ 两个安全切面。采种机和上方种植机最终位于
$y=15$。随后推测性切面把“下方种植机 + 砂叶粉碎机 + 三台研磨机 + 协议存储箱”作为同一个

相对上一版 $18\\times36$ 产线跨度，本轮共减少四行、$72$ 格包围面积和 $34$ 个传送带格；
仓库基段不计入本次面积差。

把前一轮已经找到的优质端口结构丢掉。当前获胜候选联合释放砂叶粉碎机汇入三台研磨机的三条线，
真实交叉从 $32$ 降到 $28$，纯转弯从 $31$ 降到 $30$；三条线路合计由 $36$ 格降到 $31$ 格，
相对端点曼哈顿距离的额外绕行由 $6$ 格降到 $2$ 格。两者合计从批量消行后的 $63$ 降到 $58$。
推测性切面进一步把尺寸从 $18\\times33$ 降到 $18\\times32$、传送带从 $239$ 降到 $232$，
同时保持真实交叉 $28$、纯转弯 $30$ 不变。最终前沿溢出为 $0$，全部 $22$ 条连接、吞吐和
供电校验均通过。

$(2,25,90^\circ)$ 移到 $(3,23,90^\circ)$，同带的砂叶粉碎机在种植机五格高度范围内滑动并

后，左右边缘各释放出一条源石粉末直通走廊；交替消行又把三台研磨机上移到 $y=31$，协议
存储箱上移到 $y=35$，先把布局压到 $18\\times30$。

两条采种循环水平线各由 $10$ 格、$6$ 个交叉降为 $4$ 格、$2$ 个交叉；采种机到下方种植机由
$6$ 格、$2$ 个交叉降为 $5$ 格、$0$ 个交叉。最左和最右源石粉碎机到研磨机均由 $30$ 格降到
$18$ 格且不再交叉，另外两条侧边线路也分别降到 $21$ 与 $22$ 格并消除交叉。全局真实交叉由
$23$ 降到 $9$，纯转弯由 $25$ 降到 $23$，物流格由 $203$ 降到 $170$；布局由

扩散器后，前沿溢出仍为 $0$，全部 $22$ 条连接、吞吐和供电校验继续通过。

#### 阶段十二：取货口宽度规划与初步全局层级交错

严格局部闭包不再包含“把终端设备插入直接上游设备行”的动作，因为该动作改变了拓扑层共享的
物理带。`scope=global` 才会启动这条全局邻域；如果只想验证它而不展开 CP-SAT、ejection chain
和全图 LNS，可设置 `search.globalNeighborhoods: "layer-interlock"`。默认值 `"all"` 继续运行
全部全局邻域。

生成坐标候选和启动 A* 之前，优化器按取货口实际前沿轴计算必要宽度下界：

$$
W_{\mathrm{need}}
=\sum_{i\in T}W_i
+\sum_{j\in U}W_j
+N_{U\rightarrow T}
\le W_{\mathrm{frontage}},
$$

其中 $T$ 是向同一目标存储输出的终端层设备组，$U$ 是准备插入的直接上游物理行，
$N_{U\rightarrow T}$ 是两组之间必须同时保留的物流连接数，每条至少占一个路由列。该条件是必要
条件而不是充分条件：通过后仍须完整选择端口、重布全部受影响线路、放置供电，并验收硬前沿、
连通、吞吐和目标向量；不通过则能在布局前证明当前层族无解。

中容谷地电池满足 $6+3+3+2=14\le15$，所以可把装配机交错进两台配件机所在高度带；致密源石
粉末的三台研磨机构成 $3\times6=18$ 格终端层，已经耗尽 18 格前沿，插入任何设备或路由列都会
被 `terminal-layer-saturates-frontage` 拒绝。判定不读取配方名、物品名或设备 ID，只读取卸货口
前沿、设备投影宽度和实际有向物流连接。

全局报告通过 `globalLayerInterlockCandidatesGenerated`、
`globalLayerInterlockWidthRejected`、`globalLayerInterlockCandidatesRouted`、
`globalLayerInterlockCandidatesImproved`、`globalLayerInterlockPasses`、
`globalLayerInterlockTransitions` 和 `globalLayerInterlockStoppedBy` 记录宽度筛选、完整路由与停止原因。
每次接受跨层状态后都会重新运行不含跨层动作的通用局部闭包，消除新出现的直带切面并重新安置
边缘存储和供电；完整一轮没有改善才结束。

#### 阶段十三：仓库前沿硬约束修复

单个取货口也按自身三格宽度建立前沿，不再跳过检查。当 `frontageConstraint` 为 `hard` 时，
卸货口前沿跨度外不能存在任何物理设备或传送带，包括标记为免计费的取货口供料带。初始候选
失败后，优化器会保留最接近可行的布局，根据路由失败前沿移动阻挡设备，执行最多五层定向回溯，
再尝试全局 LNS 或局部 CP-SAT 跳跃。最终仍不可行时，错误会报告剩余溢出格、相关设备和最接近
成功的失败连接。

#### 阶段十四：生成蓝图并验收

最优候选会转换为标准 `BlueprintDocument`，其中包含生产设备、配方配置、传送带、管道、跨线
连接器、仓储设施、slot link 和供电扩散器。随后使用项目现有拓扑编译器进行最终验证：

- `productionConnectivityVerified`：所有规划线路形成物理连接、拓扑无错误且设备必需输入已连接；
- `productionThroughputVerified`：每台设备输入和需要送往下游或目标存储的输出都有足够 lane 流量；
- `powerCoverageVerified`：所有声明 `requiresPower` 的设备（包括协议存储箱）都位于供电扩散器覆盖范围内。

吞吐验收证明规划 lane 的额定容量足够，不等同于完整时间轴仿真已经证明永不堵塞。最终可输出
可导入蓝图、包含完整搜索与诊断信息的 JSON 报告，以及静态 SVG 布局预览。

当前尚未自动插入通用分流器和汇流器；
端口数量不足时会明确失败，不会让设备或物流格重叠。`productionConnectivityVerified` 表示所有
已规划内部/边界线路均形成物理拓扑且编译无错误，不等同于完整时间轴吞吐率证明。

源码入口：

- `src/app`：应用外壳、面板、对话框、PWA、输入手势和工作台状态。
- `src/editor`：编辑器状态、放置校验、选区、历史、物流草稿和文档操作。
- `src/simulation`：仿真主机、Worker 协议、拓扑编译和运行时阶段。
- `src/renderer`：Pixi 渲染、贴图、装饰层和蓝图预览。
- `src/registry`：建筑、物品、配方等注册表定义。
- `src/domain`：跨模块契约、状态类型和动作/查询接口。
- `src/shared`：存储、主题、几何、浏览器环境判断、蓝图库和公共工具。
